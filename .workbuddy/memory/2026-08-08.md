### 踩过的坑（重要）
1. **MySQL 保留字 `rank`**：MyBatis-Plus 生成 `rank_no AS rank` 或直接 `rank` 列都会 SQL 报错。解法：DDL 用反引号 `` `rank` `` 建列，实体 `@TableField("`rank`")` 映射。
2. **candidate 表需要 votes 列**：实时票数存 `candidate.votes`（投票 +1 / 撤回 -1），否则 MyBatis-Plus 报 Unknown column 'votes'。
3. **MyBatis-Plus `set(字段, null)` 默认忽略 null**：清理 rank 要用 `.setSql("`rank` = NULL")` 强制置空。
4. **tally 清理逻辑**：清理非当选/非平票候选时，必须保留历史当选者（`is_winner=1` 跳过），否则重投轮会把第一轮当选者清掉。
5. **Maven 打包被占用**：旧 java 进程占着 target/voting-backend.jar → repackage 失败。先 `taskkill /PID <pid> /F`（单斜杠）再删 jar 重打。
6. **后端启动必须加 `-Dserver.port=8080`**（WorkBuddy 注入 SERVER__PORT=62950 会顶端口）。

- **排查**：WS 实测当前 8080 后端**已是新代码**（投票→admin WS 收到 4 条 themeUpdate→参与统计 voted=True）→ 后端无误
- **真根因（前端）**：`connectWs()` 只在 `Login.vue` 登录成功时调用；**刷新页面后 token 在 localStorage、路由直接进页面、Login 不执行 → WS 永不重建** → 管理页收不到任何推送，只有手动点统计(触发 loadAll)才刷新
- **修复**：`App.vue` 增加 `onMounted(() => connectWs())`——应用启动即尝试连接（未登录时 ws.js connect 内部 `if(!token) return` 安全跳过）；同时修复了投票端刷新后 leader 不在线的问题
- 前端已构建验证 ✓

## 在线用户去重 Bug（08-09 10:08 用户反馈）
- **症状**：投票端退出后管理端仍显示在线；同一用户再次进入后参与统计重复（如 001 出现两次）
- **根因**：`WsSessionManager` 用 `sessionId` 作 Map key，同一用户多开/重连/刷新页面都会产生多个 session 条目，且 `onlineLeaders()` 遍历所有 entries 不过滤
- **修复**：新增 `userSessions: Map<Long, WebSocketSession>`（userId -> session），`add()` 时先 `put(userId, new_session)` 拿到旧 session → 主动关闭并从 sessions/sessionUsers 移除；`onlineLeaders()` 改为遍历 `userSessions.values()`（天然去重）；`remove()` 仅当 `userSessions.get(userId) == session` 才移除（避免误关新连接）
- **验证**（8080 临时实例）：001 开 2 个 WS → 在线只 1 次 ✓；关 ws1 → 仍 1 次（去重保留另一连接）✓；关 ws2 → 0 次 ✓

## 投票支持弃权/不足额提交（08-09 10:16）
- 用户需求：可不足额提交（只想投几个人）→ 进一步：**空票(弃权)也可提交**
- **后端 `VoteService.submit`**：① 去掉「请至少选择一名」校验，`candidateIds` 为 null 时置空 ArrayList（空票只记 ballot 不记 item）；② 正常投票去掉「必须选满」(无分类 `< quota` / 有分类 `!= Σ分类名额`) 校验，只保留上限（无分类 `> quota` / 分类 `> cat.quota`）；重投轮逻辑不变（限额=分类空缺）
- **前端 `VoteHome.vue`**：`canSubmit` 改为 voting 且未投即 true（0 选可提交）；删除 submit() 里的选满校验；submitTip 文案改为「可直接提交（可弃权，或选择部分/全部名额）」
- **验证**（8080 临时实例，cat+single 两主题×4场景）：空票✓ 部分2/5✓ 满额5/5✓ 超限6/5被拒✓；tally 后空票不影响当选（无票候选不当选）✓
- 边界：重投轮全部弃权时并列无法决出（tally 无票不当选），管理员可再次重投或清除数据——属预期
